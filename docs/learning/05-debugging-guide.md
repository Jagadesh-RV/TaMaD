# TaMaD Complete Learning Knowledge Base — Debugging Manual

> Use this guide when things break. It outlines the most common failure points in the TaMaD stack and exactly how to trace them.

## 39 — Debugging Manual

### Scenario 1: "I'm logged out immediately after logging in"
**The problem**: Token refresh is failing, or cookies aren't being set.

**How to debug**:
1. Open Browser DevTools → Application → Cookies. Check if `tamad_access_token` and `tamad_refresh_token` exist.
2. If they don't exist: The backend isn't sending them properly.
   - Check `backend/src/controllers/authController.ts` in `createFirebaseSession`.
   - Ensure the frontend request includes `withCredentials: true`.
3. If they do exist, but disappear: Check the Network tab for the `/api/v1/auth/refresh` request.
   - Did it return 401? Check the backend logs.
   - Is `sameSite: 'lax'` blocking cookies because of frontend/backend domain mismatches? (This happens if frontend is `127.0.0.1` but backend is `localhost`).

### Scenario 2: "Real-time updates aren't working"
**The problem**: Socket.IO connection failed, or the user didn't join the correct room.

**How to debug**:
1. Check the browser console. Look for Socket.IO connection errors.
2. In React DevTools, inspect `RealtimeProvider`. Is `isConnected` true?
3. Check backend logs for rate limiter warnings: `Socket [id] exceeded rate limit`.
4. Are you receiving events for the WRONG workspace? Check that `emit('join_workspace', workspaceId)` was called when the user switched workspaces (handled in `WorkspaceSwitcher.tsx` or `AppLayout.tsx`).

### Scenario 3: "Changes aren't showing up after I refresh"
**The problem**: Aggressive Redis caching.

**How to debug**:
1. You created a Task, but the `/tasks` list didn't update.
2. The `createTask` controller must invalidate the cache: `cache.invalidatePattern(CACHE_KEYS.TASKS(workspaceId, '*'))`.
3. Check `backend/src/controllers/taskController.ts` to ensure the invalidation pattern exactly matches the cache key generated by `cacheMiddleware`.

### Scenario 4: "CORS Error: Blocked by CORS policy"
**The problem**: The frontend origin isn't allowed by the backend.

**How to debug**:
1. If using the Vite proxy (`/api`), CORS shouldn't happen because the browser thinks it's talking to the frontend server.
2. If the frontend is bypassing the proxy (e.g., hitting `http://localhost:5002` directly), check `process.env.CORS_ORIGIN` in the backend `.env`. It must exactly match the frontend URL (no trailing slash).

### Scenario 5: "Cannot read properties of undefined (reading 'xyz')" in React
**The problem**: A component is trying to render data before the Zustand store finishes loading it.

**How to debug**:
1. Check the Zustand store's `loading` state.
2. Ensure the component returns a loading spinner if data isn't ready:
   ```tsx
   const { items, loading } = useFeatureStore();
   if (loading) return <Spinner />;
   if (!items) return null; // Safe guard
   ```

### Quick Diagnostic Commands

**Tail backend logs in Docker:**
```bash
docker logs -f tamad_backend
```

**Check Redis keys:**
```bash
docker exec -it tamad_redis redis-cli
127.0.0.1:6379> keys *
127.0.0.1:6379> flushall   # Emergency cache clear
```

**Check MongoDB connections:**
```bash
docker exec -it tamad_mongo mongosh
test> use tamad
tamad> db.currentOp()
```
